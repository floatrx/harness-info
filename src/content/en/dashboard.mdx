## Open it

In the harness-demo checkout, run:

```bash
pnpm dashboard
```

Then open `http://127.0.0.1:4777`. The dashboard listens on 127.0.0.1 only. Its buttons write the same files as the
CLI, so you can use both side by side. What Start, Pause, Resume and Stop do is on [Running the loop](/loop).

Each project opens on Home. It is for the person who just came back: how many cards wait for you and why, what is
done, what runs now, and what the work cost. Every tile links to the board filtered to what it counts, for example
`?owner=human`. How such a page is built is on [Build your own dashboard](/build-dashboard).

## Learning

Learning turns repeated failures into rules. It finds candidates in the trace: one violation that parked two tasks, a
tool denied in three units, a verdict that sent one task back twice, and the notes agents leave in `JOURNAL.md`. You
edit the draft rule and press Apply; it goes into `.harness/LESSONS.md`, and every later unit reads it in its Memory.
Reject records the candidate so it is never proposed again; Undo withdraws an applied rule. The CLI does the same:

```bash
harness lessons --project bookmarks
harness lessons apply <key> "<rule text>" --project bookmarks
harness lessons reject <key> --project bookmarks
harness lessons withdraw L-001 --project bookmarks
```

A decision made while a unit runs is safe: the write ledger excuses `LESSONS.md` the way it excuses a task file.

## Stats

Stats adds up the usage each unit reported, per stage and per task. Cost is the API-equivalent price `claude -p`
reports: a subscription login is not billed per token, and usage limits apply instead. `harness stats` prints the same
tables in the terminal.
